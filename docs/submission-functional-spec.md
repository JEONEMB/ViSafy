## 1. MVP 구현 범위

한국에 거주하는 외국인이 **"나는 이 금융상품을 이용할 수 있는가"** 를 공식 문서 근거와 함께 확인하고,
**은행 창구에서 실제로 거래를 끝낼 수 있도록** 준비물과 대화까지 전달받는 범위까지 구현했다.

구현 범위를 다섯 갈래로 정리하면 다음과 같다.

**(1) 공식 Source 파이프라인**
관리자가 공식 도메인 allowlist에 등록된 금융기관 문서를 Source로 등록하고, 원문 Snapshot과 SHA-256
content hash를 보존한다. LLM이 Snapshot에서 가입조건 후보를 제안하면 규칙 기반 검증기가 원문과
대조하고, 사람이 승인한 것만 Runtime 판정에 쓰인다. 같은 URL의 hash가 바뀌면 기존 승인본을 재검수
대기로 전환하고 사용자에게 변경 사실을 알린다.

**(2) 결정론적 사전자격 판정 (Eligibility)**
승인된 공개 가입조건과 사용자 프로필을 규칙 엔진이 결정론적으로 비교한다. 조건 충돌은 임의 선택 없이
`SOURCE_CONFLICT`, 근거 부재는 `INSUFFICIENT_INFORMATION`, 비공개 조건은 `NEED_BANK_CONFIRMATION`으로
처리한다.

**(3) 이용 가능성 판정 (Access)**
가입조건 충족과 별개로 신분확인 방법·필요서류·영업점/모바일 채널 이용 가능성을 따로 판정한다.
채널 근거 하나로 영업점과 모바일을 모두 가능하다고 추론하지 않는다.

**(4) 공식 문서 기반 AI 설명·검색**
승인·유효한 해당 상품의 Source만 대상으로 6개 언어 의미 검색을 수행하고, 검색된 원문과 구조화된 판정
결과만으로 쉬운 설명·다음 행동·은행 문의문을 생성한다.

**(5) 은행 방문 패킷**
진단 결과를 창구에서 그대로 쓸 수 있는 한 장의 준비 문서로 조립한다. 가져갈 서류(한국어 원문 병기),
창구에서 보여줄 한국어 문장, 은행원 예상 질문과 답변 선택지, 공식 신청 절차, 공식 근거로 구성된다.

전 화면·판정 메시지·서류 안내·AI 답변이 **한국어·영어·베트남어·중국어·일본어·태국어 6개 언어**로
제공된다(영어 대체 없음).

**현재 데이터**: 활성 상품 11개, 금융기관 4곳(KB국민은행·신한은행·하나은행·KB증권),
승인·유효 공식 Source 26개, Evidence 연결률 100%. 근거가 부족한 상품은 의도적으로 `PARTIAL`(2개),
`NOT_READY`(1개)로 남겨 두었다.

## 3. 사용자 이용 흐름

배포 URL 접속 후 순서다. **로그인이나 계정 발급 없이 바로 진행된다.**

1. **언어 선택** — <https://34-64-228-103.sslip.io> 접속 후 6개 언어 중 하나를 선택한다.
2. **금융 목적 선택** — 지금 가장 필요한 금융서비스를 고르고 **내 금융생활 시작하기**를 누른다.
3. **임시 프로필 입력** — 국적과 현재 준비상태(신분증·휴대전화·본인인증·국내계좌 보유 여부)를 입력한다.
   식별번호는 입력하지 않는다. 저장 후 **내게 필요한 금융서비스 보기**를 누른다.
4. **추천과 여정 확인** — 일반상품과 외국인 특화상품이 함께 제시된다. 상단에서 지금 준비할 한 가지
   행동을, Financial Journey에서 현재 단계를 확인한다.
5. **상품 선택과 사전자격 진단** — 상품 카드를 열고, 해당 상품이 요구하는 추가 정보만 입력한 뒤
   **내 프로필로 사전자격 확인**을 누른다. 공개조건 충족 여부, 금융기관 확인사항, 신분확인 방법,
   영업점·모바일 이용 방법이 나온다.
6. **근거 확인** — 판단 근거 / 필요서류 / 신청 절차 / 공식 정보 탭에서 원문 발췌와 정보 기준일,
   금융기관 공식 페이지 링크를 확인한다.
7. **공식 문서에 질문** — 검수된 조건에 대해 선택한 언어로 질문한다. 답변에는 출처 문서가 함께 붙고,
   근거가 없으면 답을 만들지 않고 금융기관 확인이 필요하다고 안내한다.
8. **은행 방문 패킷 열기** — 상품 상세 상단의 패킷 버튼으로 이동한다. 서류 목록, 창구에서 보여줄
   한국어 문장, 은행원 예상 질문과 답변 선택지, 신청 절차, 공식 근거가 한 장에 정리된다.
   **창구에서 보여주기**로 한국어 문장을 전체화면으로 띄우거나 인쇄·PDF 저장할 수 있다.

> 3~8단계는 프로필 생성 시각으로부터 24시간 안에서 유지된다. 24시간이 지나면 프로필과 진단 결과가
> 만료되며, 처음부터 다시 진행하면 된다.

## 4. AI 및 데이터 처리 방식

### 4-1. AI가 수행하는 역할 — 그리고 수행하지 않는 역할

AI는 다섯 지점에서 동작하며, **어느 지점에서도 사전자격을 판정하지 않는다.**

| AI 기능 | 수행 역할 | 안전 경계 |
| --- | --- | --- |
| 조건 후보 추출 | 공식 Snapshot을 읽어 가입조건 후보를 제안 | 인용문이 원문에 없거나, 원문에 없는 숫자·비자코드를 쓰거나, 규칙 엔진 비교 형식과 다르면 **저장 자체를 하지 않음**. 저장돼도 사람 승인 전에는 판정에 미사용. LLM 장애 시 규칙 기반 추출로 자동 복귀 |
| 공식 Source 검색 (RAG) | 해당 상품의 승인·유효 Source만 6개 언어 의미 검색 | 다른 상품, 미승인·만료 Source, 비공식 도메인 배제 |
| 설명 생성 | 쉬운 설명·다음 행동·은행 문의문 생성 | 판정 결과와 숫자를 **읽기 전용**으로만 사용. 실패 시 검증된 6개 언어 템플릿으로 자동 전환 |
| 상품 한정 대화 | 해당 상품의 공식문서에 대한 후속 질문 응답 | 일반 투자·대출 추천 대화로 확장하지 않음 |
| 준비 안내 조립 | 프로필과 판정 결과에 따라 패킷의 서류·문장·질문 구성 | 어떤 답변 선택지도 사용자가 조건을 충족한다고 주장하게 만들지 않음. 사실 진술 또는 질문만 |

**권한 경계**

```text
공식 Source → LLM 조건 후보 제안 → 규칙 기반 원문 대조 검증 → 사람의 Human Verification
           → 규칙 엔진 판정(결정론적) → RAG 검색 → LLM 설명
```

LLM 출력 스키마에는 **상태 필드가 존재하지 않는다.** Eligibility와 Access 판정값은 Backend가 계산한
뒤 응답 조립 단계에서 고정되므로, LLM이 판정을 생성하거나 변경할 수 없다. OpenAI 호출이 실패해도
사전자격 진단·근거 검색·6개 언어 설명은 그대로 동작한다.

### 4-2. 사용 데이터

| 구분 | 내용 |
| --- | --- |
| 지식 원천 | 금융기관 공식 도메인의 상품페이지·상품설명서·약관 Snapshot (승인·유효한 것만) |
| 검색 색인 | FastEmbed `intfloat/multilingual-e5-small`(384차원) 기반 벡터 색인. 판정 기준이 아닌 검색용 |

| 생성 모델 | OpenAI Responses API. 구조화 출력(JSON Schema strict), 대화 저장 없음(`store=false`) |

### 4-4. 개인정보 및 민감정보 처리

**수집하지 않는 항목** — 주민등록번호, 외국인등록번호 원문, 여권번호, 계좌번호, 카드번호, 비밀번호,
신용점수. 임시 프로필에 **해당 필드 자체가 존재하지 않으며**, 자유입력 칸에 해당 형식의 값을 붙여넣어도
Backend가 `400 Bad Request`로 거부한다.

**수집 항목** — 국적, 금융 목적, 체류자격 구분, 신분증·국내 휴대전화·본인인증·국내계좌·신용이력의
**보유 여부**(번호 아님). 소득·재직 정보는 해당 상품의 공식 조건이 실제로 요구할 때만 추가로 묻는다.

**보관과 파기** — 로그인 없이 UUID 세션에 묶인 임시 프로필로 **24시간 후 만료**된다. 숫자 ID만으로는
조회할 수 없고 생성 시 발급된 세션 UUID를 헤더로 함께 보내야 하며, 다른 세션에는 존재 여부조차
노출하지 않고 `404`를 반환한다. 진단 결과에는 프로필 원문 대신 SHA-256 해시를 저장한다.

**AI 전송** — LLM에는 검색된 공식 원문과 구조화된 판정 결과만 전달한다. 대화는 OpenAI에 저장되지
않으며(`store=false`), 사용자 질문은 신뢰할 수 없는 입력으로만 취급해 Prompt Injection을 검색 전에
차단한다.

**적용 가드레일 15종** — `OFFICIAL_SOURCE_ONLY`, `PRODUCT_METADATA_FILTER`,
`ELIGIBILITY_RESULT_IMMUTABLE`, `NO_APPROVAL_GUARANTEE`, `STRUCTURED_VALUES_ONLY`,
`RETRIEVED_TEXT_IS_EVIDENCE_NOT_INSTRUCTION`, `USER_QUERY_IS_UNTRUSTED_INPUT`,
`NO_FOREIGNER_INELIGIBILITY_INFERENCE`, `NO_REAL_NAME_FOREIGNER_ACCESS_INFERENCE`,
`NO_UNSOURCED_VISA_RULE`, `NO_UNSOURCED_CHANNEL_AVAILABILITY`, `NO_APPROVAL_PROBABILITY`,
`NO_CREDIT_SCORE_INFERENCE`, `NO_INTERNAL_REVIEW_INFERENCE`, `NO_INTERNAL_CODE_EXPOSURE`.

**없다.** 주요 기능은 전부 로그인 없이 확인할 수 있다. 임시 프로필은 화면에서 즉시 생성되며 24시간 후

영어 대체는 발생하지 않는다.

### 5-5. 실행 환경 및 브라우저 제한사항

| 항목 | 내용 |
| --- | --- |
| 권장 브라우저 | Chrome, Edge, Safari 최신 버전 (Chromium 기준 개발·검증) |
| 모바일 | 지원. 360px 폭까지 가로 스크롤 없이 동작하도록 검증 |

### 5-6. MVP 단계의 제한사항

- **공식 Source Snapshot은 관리자가 등록한다.** 실시간 자동 수집(Crawling)은 수행하지 않는다.
- **상품 수보다 근거의 완전성을 우선했다.** 활성 상품 11개 중 근거가 부족한 3개는 임의로 채우지 않고
  `PARTIAL`·`NOT_READY`로 남겨 두었다.
- 필요서류·신청절차는 등록·조회 중심이며, 수정 UI와 변경 이력은 이번 범위에 포함하지 않았다.
- 관리자 인증은 MVP 기준 HTTP Basic이다. HTTPS 환경에서만 사용하며, 실서비스 전환 시 JWT HttpOnly
  쿠키 또는 조직 SSO로 교체가 필요하다.
- 색인 실행 이력·응답 지연·오류율에 대한 운영 관측 화면은 이번 범위에 포함하지 않았다.
- **SSAFIN은 가입 가능성을 보장하지 않는다.** 모든 결과는 방문·신청 전 준비 안내이며 최종 심사는
  금융기관이 수행한다. 이 문구는 6개 언어로 모든 진단 결과에 표시된다.
